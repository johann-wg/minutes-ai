# minutes-ai

会議録や問い合わせメールから、**決定事項・タスク（担当・期限）・未決事項**を抽出する Python CLI です。
Claude API（Anthropic）を使い、日本語・韓国語・日韓混在のテキストを日本語で整理して、Excel のタスク管理表と Markdown の議事録に出力します。

すべての抽出項目に**原文からの引用（根拠）**を付け、その引用が原文に実在するかをプログラムで検証します。
LLM が原文にない内容を作り出した場合は「要確認」として表示し、人が確認すべき箇所が分かるようにしています。

```
$ minutes-ai extract data/dev/d06_support_bridge.txt --date 2026-10-22 --model claude-haiku-5-5 --xlsx tasks.xlsx

## 決定事項
- 次回定例を11月5日に変更し、確定する
- 暫定の回避策として手動での再実行手順を採用する

## タスク
| 担当 | タスク | 期限 |
|---|---|---|
| 박서준 | 夜間バッチ停止の分析結果を次の火曜日までに回信する | 2026-10-27 |
| 清水 | お客様に手動での再実行手順を本日中に案内する | 2026-10-22 |

## 未決事項
- 恒久対策のリリース時期は未定（原因分析が終わるまで判断できない）

## 要確認（根拠が原文に見つからない項目）
- 分析 결과는 다음 주 화요일까지 회신드리겠습니다.
```

最後の項目は、韓国語の原文 `로그는 받았습니다. 분석 결과는…` を LLM が一部日本語に書き換えて引用したため、検証で検出されたものです。
出力例の全体は [examples/](examples/) にあります（Excel の [タスク管理表](examples/d06_support_bridge.xlsx) を含む）。

## 背景

日韓の技術連携の業務で、週 2 回の顧客会議の議事録作成、問い合わせの整理、日韓翻訳を担当しています。
会議のたびに「何が決まったか」「誰がいつまでに何をするか」「何が持ち越しか」を手作業で整理しており、
この作業を自動化しつつ、**生成 AI の出力をそのまま信用せずに検証できる形**にすることを目指しました。

設計で重視した点:

- **根拠の検証**: 各項目に原文の引用を付けさせ、引用が原文に存在するかを機械的に確認する（表記の揺れ・全角半角・空白は正規化）
- **期限の正規化**: 「明後日」「来週水曜」などの相対的な表現を、会議日を基準に `YYYY-MM-DD` に変換させる。会議中に変更された期限は最終的な値にする
- **抽出しないものの明確化**: 取り消された・他の人に移ったタスクや、「いつか〜したい」という願望はタスクに含めない
- **評価による改善**: 正解データで適合率・再現率を測定し、モデルごとの精度と費用を比較する
- **再現性と費用**: LLM の応答をキャッシュしてコミットし、API キーがなくても評価結果を再現できる。開発中は安価なモデルで反復する

## 仕組み

```
 テキスト ──> extract (Claude API, JSON スキーマで出力形式を固定) ──> grounding (引用の実在チェック)
                     │                                                        │
               llm-cache/ (応答のキャッシュ)                     export ──> Excel / Markdown
                                                                              
 data/{dev,test}/*.gold.json (正解) ──> evaluate (適合率・再現率・期限・根拠の実在率)
```

| モジュール | 役割 |
|---|---|
| `extract.py` | プロンプトと JSON スキーマ（Structured Outputs）で抽出。応答キャッシュ、トークン使用量・費用の集計 |
| `grounding.py` | 引用（quote）が原文に存在するかの検証 |
| `evaluate.py` | 正解データとの照合。タスクは担当者と内容の両方が一致したときに正解とし、期限は別に採点 |
| `export.py` | Excel（タスク / 決定事項 / 未決事項の 3 シート、要確認の行は色付け）と Markdown を出力 |

## 使い方

```bash
git clone https://github.com/johann-wg/minutes-ai.git
cd minutes-ai
pip install -e .

# ANTHROPIC_API_KEY を設定して実行
minutes-ai extract meeting.txt --date 2026-10-22 --xlsx tasks.xlsx --md minutes.md
minutes-ai extract meeting.txt --date 2026-10-22 --model claude-haiku-5-5   # 安価なモデル

# 評価 (キャッシュのみ使用・API キー不要)
minutes-ai eval data/test --model claude-sonnet-5-5 --offline
```

`--model` を省略した場合は `claude-opus-5-5` を使います。実行後に API 呼び出し回数と費用が表示されます。

## 評価結果

正解データは架空の会議・問い合わせ 12 件です（業務のデータは一切含みません）。

| データ | 件数 | 用途 |
|---|---|---|
| `data/dev/` | 6 | 開発用。プロンプトの調整に使用 |
| `data/test/` | 6 | **評価専用**。プロンプトの調整には使わない。正解は実行前に作成して固定 |

日本語のみ 8 件、韓国語のみ 3 件、日韓混在 1 件で、期限の変更・担当者の変更・取り消されたタスク・願望だけの発言などを含みます。

### 評価専用データでのモデル比較

| モデル | 決定事項 F1 | タスク F1 | 未決事項 F1 | 期限の正解率 | 根拠の実在率 | 会議 100 件あたり費用 |
|---|---|---|---|---|---|---|
| Claude Haiku 5.5 | 1.00 | 1.00 | 1.00 | 12/13 | 26/26 | 約 $0.07 |
| Claude Sonnet 5.5 | 0.93 | 1.00 | 1.00 | 13/13 | 27/27 | 約 $0.94 |
| Claude Opus 5.5 | 0.93 | 0.85 | 0.83 | 11/11 | 27/27 | 約 $1.98 |

各モデル 1 回ずつの結果です（[docs/model-comparison.md](docs/model-comparison.md)、`scripts/compare_models.py` で生成）。件数が少ないため、差の大きさより誤りの内容を重視しています。

誤りの内容:

- **Haiku**: 「来週火曜 → 水曜に変更」と会議中に期限が変わったタスクで、最終的な期限（11/4）を誤った
- **Opus**: 韓国語の会議 1 件で、出力言語（日本語）の指示に従わず韓国語で出力したため、その会議のタスク・未決事項が一致しなかった
- **Sonnet / Opus**: 「ユーザー教育は B 社が実施するため自社の作業はない」を決定事項として抽出（正解データでは対象外としたが、決定事項と見なす解釈もあり得る）

### 開発中の改善

| 版 | 変更 | 開発用データでのタスク F1（Haiku） |
|---|---|---|
| v1 | 初版 | 0.88 — 韓国語の会議でタスクを韓国語のまま出力し、照合できなかった |
| v2 | 「入力の言語にかかわらず出力言語で書く」を明記 | 1.00 |

v2 の開発用データでは、根拠の検証により、LLM が韓国語の原文を日本語に書き換えて引用した 2 件を検出しました（根拠の実在率 30/32）。
